# Freeminer mod compatibility

The `freeminer` mod can be installed in a world or user mod directory and
enabled for a game. It targets the Freeminer engine, including its mapgen,
climate, liquid, and node-physics extensions. It does not require changes to
the target game's files. Optional dependencies load the adapter after the
relevant game mods; the Default Game can still use its existing first/last
mod hooks.

* **Default Game:** retains the existing game-specific integration.
* **Minetest Game:** loads the Default-based node, ice tree, lava tree,
  map-bound, Arnis, fire, recipe, and additional-ore features. Aquatic plants
  that use Marinara are enabled when Marinara is installed. The ore noise
  changes applied by Default Game during ore registration are not replayed
  into Minetest Game's already registered ores.
* **VoxeLibre:** adapts available stone, soil, sand, liquids, trees, fire,
  ice and lava trees, recipes, and Arnis features to VoxeLibre node names.
  It keeps VoxeLibre's liquid parameter types and its own fire and mapgen
  systems. Default Game's ore and aquatic-plant definitions are not ported
  to VoxeLibre; Marinara-specific plants require Marinara and a separate
  game adapter.

Third-party mods designed for a different game may need adaptation or may
need to be disabled in that world. The portals mod supports Default Game and VoxeLibre obsidian nodes.
The sponge mod currently has no declared
`default` dependency, but its liquid checks and recipes use `default` item
names and do not work as intended in VoxeLibre. Existing world nodes and
generated mapblocks are not retroactively regenerated by installing the mod.
